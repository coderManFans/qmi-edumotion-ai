# EduMotion AI 产品需求规格说明书（PRODUCT_SPEC）

-   文档版本：1.0
-   状态：MVP 设计基线
-   产品代号：EduMotion AI
-   产品定位：面向中小学题目与知识内容的 AI 教学讲解生成系统
-   目标部署：本地优先，架构预留云端迁移能力

------------------------------------------------------------------------

## 1. 产品概述

### 1.1 产品愿景

EduMotion AI
将中小学题目、阅读材料或知识点转换为易理解、可播放、可编辑的教学内容。用户输入文字、图片或
PDF，系统识别并理解内容，生成结构化教学脚本，再由统一的渲染体系输出：

1.  动画讲解视频：MP4，包含画面、旁白、字幕和必要的背景音。
2.  可滚动交互式图解：Web
    页面，按场景逐步呈现讲解内容，支持播放旁白、查看步骤和重点标注。

两种输出共用同一份 Lesson
IR（教学内容中间表示），避免视频和网页分别生成造成内容不一致。

### 1.2 产品目标

MVP 必须验证以下核心价值：

-   用户可以提交一道中小学题目或一篇短文。
-   系统能识别学科、年级、题型和关键内容。
-   系统能生成可校验、可编辑的分镜式教学脚本。
-   数学题可生成结构清晰的步骤讲解和基础动画。
-   语文短文可生成忠于原文的故事分镜、旁白和图解。
-   同一份脚本可以生成 Web 图解和 MP4。
-   长耗时生成任务有进度、日志、失败状态和重试能力。

### 1.3 非目标

MVP 不承诺以下能力：

-   不追求输入任意题目都能一次生成完美视频。
-   不训练基础大模型、图像模型或视频模型。
-   不做完整 LMS、班级管理、作业布置、考试系统。
-   不做复杂多人协作、付费订阅和商业化计费。
-   不以生成式视频模型作为所有场景的默认渲染方式。
-   不允许 LLM 直接生成并执行任意 Python、Shell 或浏览器脚本。
-   不把 AI 生成的答案视为天然正确；必须保留验证状态和人工审核入口。

## 2. 目标用户与使用场景

### 2.1 目标用户

  用户                主要诉求                         MVP 支持方式
  ------------------- -------------------------------- ---------------------------
  学生                看懂题目、理解步骤、复习知识点   观看视频、浏览分步图解
  家长                辅助孩子理解题目                 输入题目、生成讲解内容
  教师                快速制作讲解课件                 编辑脚本、预览和导出
  内容运营/教研人员   审核教学内容和素材               查看 IR、审核场景、重渲染

MVP 可先采用单用户工作台，不必实现复杂角色权限；但数据模型应保留
owner_id 和项目归属字段。

### 2.2 首批重点学科

**数学** - 小学加减乘除应用题。 - 数量关系和简单单位换算。 -
基础数轴、面积、周长、角度等几何知识。 -
通过物体数量、图形、公式和步骤动画讲解。

**语文** - 小学短篇阅读材料。 - 人物、地点、事件、情节顺序提取。 -
故事绘本式分镜。 - 阅读理解问题、原文依据和答案分析。

其他学科先采用通用图解能力，不作为 MVP 的验收门槛。

## 3. 核心用户流程

### 3.1 主流程

1.  用户创建教学任务。
2.  用户输入题目文字，或上传图片/PDF。
3.  系统执行文件校验、OCR/文本解析。
4.  用户确认识别后的原文。
5.  系统识别学科、年级、题型和教学目标。
6.  学科 Planner 生成解题方案或故事结构。
7.  Script Writer 生成 Lesson IR。
8.  Validator 检查答案、步骤、原文依据和数据结构。
9.  用户预览并编辑脚本；可选择跳过人工确认（仅限低风险任务的后续配置）。
10. 系统生成 Web 图解。
11. 系统异步生成旁白、图片/动画片段和 MP4。
12. 用户预览、下载、修改或重新渲染。

### 3.2 数学题用户流程

输入示例：

> 小红有 12 个苹果，送给小明 4 个，还剩多少个？

期望系统行为：

-   识别学科：数学。
-   识别年级：由用户选择或模型给出建议，不应仅凭题目强行确定。
-   识别知识点：减法、数量变化。
-   求解：12 - 4 = 8。
-   验证：算式结果、数量边界、单位一致。
-   分镜：原有数量 → 送出数量 → 剩余数量 → 公式与答案。
-   输出：可滚动图解和 MP4。

### 3.3 语文短文用户流程

输入一篇短文及阅读问题。系统应：

-   保留原文，不擅自改写原文事实。
-   提取人物、地点、时间、事件和情节顺序。
-   将故事内容拆分为场景。
-   对阅读问题生成答案、理由和原文段落引用。
-   对原文未明确说明的信息标记为"推断"，不得伪装成原文事实。
-   生成绘本式 Web 图解和故事视频。

### 3.4 编辑与重新生成

用户应能： - 修改标题、讲解词、字幕和场景顺序。 -
修改场景视觉风格和动画时长。 - 锁定已确认的场景，避免后续生成覆盖。 -
只重新生成指定场景或指定输出资产。 -
查看每次生成的版本、状态和错误信息。

## 4. 功能需求

### 4.1 输入与素材管理

  ID      需求                 优先级   验收标准
  ------- -------------------- -------- ------------------------
  IN-01   支持粘贴文本         P0       创建任务后保存原始文本
  IN-02   支持 JPG/PNG 上传    P0       文件校验、保存、可查看
  IN-03   支持 PDF 上传        P1       能提取文本或逐页 OCR
  IN-04   OCR 结果可编辑       P0       用户能修正识别错误
  IN-05   记录来源文件         P0       原始文件与 lesson 关联
  IN-06   限制文件大小和类型   P0       超限请求被拒绝并提示

### 4.2 题目理解与教学脚本

  ID      需求             优先级   验收标准
  ------- ---------------- -------- --------------------------------
  AI-01   学科/题型分类    P0       返回结构化分类及置信度
  AI-02   年级建议         P1       可由用户覆盖
  AI-03   数学步骤规划     P0       生成步骤、算式和答案
  AI-04   语文故事拆解     P0       人物、场景、事件有来源依据
  AI-05   生成 Lesson IR   P0       通过 Pydantic/JSON Schema 校验
  AI-06   答案验证         P0       输出验证状态和证据
  AI-07   脚本人工编辑     P0       修改后形成新版本
  AI-08   质量审核         P1       标记事实、教学和视觉问题

### 4.3 Web 交互图解

-   根据 Lesson IR 的 scenes 顺序渲染页面。
-   支持逐场景滚动、目录导航和当前场景高亮。
-   支持旁白播放/暂停和字幕显示。
-   数学场景支持数字、算式、图形和数量对象。
-   故事场景支持图片、人物标签、旁白和原文引用。
-   页面在桌面和移动端可用。
-   场景渲染失败时显示可理解的错误状态，不应导致整课白屏。

### 4.4 视频生成

-   P0：Manim 数学模板、静态图片场景、简单镜头动画、TTS、FFmpeg 合成。
-   P1：ComfyUI 图片生成、角色参考图、图片风格统一。
-   P2：图片转视频/生成式视频、复杂转场、更多画幅和多语言。

视频至少支持： - 16:9 横屏。 - MP4 容器。 -
字幕烧录或独立字幕文件（二选一先实现）。 - 旁白音轨。 -
生成状态、日志和失败原因。 - 对单个场景重渲染。

### 4.5 任务管理

-   生成任务异步执行。
-   状态至少包括
    CREATED、PARSING、ANALYZING、SCRIPT_GENERATING、REVIEWING、WAITING_FOR_APPROVAL、RENDERING、COMPLETED、FAILED、CANCELLED。
-   每个阶段记录开始时间、结束时间、进度和错误。
-   支持幂等任务提交和失败重试。
-   任务状态通过轮询或 SSE 更新。
-   Worker 重启后，任务状态不能无故丢失。

## 5. MVP 范围与阶段

### 5.1 MVP 必做（P0）

1.  文本输入和图片上传。
2.  OCR 结果确认与修改。
3.  数学/语文两类内容路由。
4.  Lesson IR v1。
5.  数学基础解题和规则验证。
6.  语文短文人物/事件/场景提取。
7.  基础 Web 场景渲染器。
8.  Manim 基础数学模板。
9.  图片场景 + 简单镜头动画。
10. 中文 TTS Provider 接口。
11. FFmpeg 合成 MP4。
12. 任务状态、日志、历史版本。
13. 本地 Docker Compose 基础部署。

### 5.2 暂缓（P1/P2）

-   完整用户/班级/学校管理。
-   多人协作与评论。
-   教材版本知识库和 RAG。
-   自动生成练习题和错题本。
-   生成式视频模型。
-   复杂 3D 动画。
-   移动 App。
-   云端多租户、计费和配额。
-   自动发布到第三方视频平台。

### 5.3 推荐验收样例集

至少建立 30 道数学题、20 篇语文短文/阅读题作为回归集。每次修改
Planner、Prompt、IR Schema 或 Renderer 后运行回归测试。

数学样例覆盖： - 加减乘除。 - 多步应用题。 - 单位和数量关系。 -
简单几何。 - 容易出现歧义的题目。

语文样例覆盖： - 单人物叙事。 - 多人物对话。 - 时间顺序。 - 因果关系。 -
阅读理解依据定位。 - 原文信息不足的推断题。

验收指标建议： - IR Schema 校验通过率：目标
100%（不合格应重试或人工修正）。 - 数学确定性题目答案校验：目标 100%
通过或明确标记失败。 - 语文场景关键事实可追溯到原文。 -
生成失败可定位到具体阶段。 -
所有完成任务都能打开图解；成功视频任务可播放 MP4。
这些是工程验收目标，不代表模型准确率保证。

## 7. 内容安全、版权与未成年人保护

-   上传文件应校验类型、大小和恶意内容。
-   不允许模型输出的任意代码直接执行。
-   渲染进程应使用受限用户、隔离目录、超时和资源限制。
-   不默认收集学生姓名、学校、联系方式等个人信息。
-   用户上传的教材、试卷、短文和图片应确认有权使用。
-   图片模型生成的人物不得冒充真实学生或教师。
-   背景音乐、字体、图片和模型权重需逐项核对许可证。
-   面向学校或未成年人上线前，需评估适用的数据保护、内容审核和未成年人相关法规。
-   保留人工审核入口，明确标记 AI 生成内容。

## 8. MVP 完成定义（Definition of Done）

一个版本只有同时满足以下条件，才算完成：

1.  可从输入端创建任务。
2.  原始题目和识别文本可追溯。
3.  生成的 IR 通过 Schema 校验。
4.  数学答案或语文原文依据有验证结果。
5.  Web 图解可正常浏览。
6.  视频可生成、播放和下载，或明确显示失败原因。
7.  任务、版本、资源元数据持久化。
8.  关键路径有自动化测试。
9.  本地部署文档可供新开发者复现。
10. 不存在任意 LLM 代码未经隔离直接执行的路径。
